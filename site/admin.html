Who administers the people

Somebody has to run the accounts, and at the start that is the volunteer. But the person who runs the accounts must not also be the person who decides what the public sees, or the review gate is decoration. This page shows how those two jobs come apart.

The one rule

The master archivist can create accounts but cannot grant release authority, and cannot approve a record. Only a Unit administrator can hand out the reviewer role, and only a reviewer can publish. The volunteer is never in that chain.

Bootstrapping

The Chief names one Unit administrator — realistically the records coordinator or a chief officer. That person then names reviewers. I set the account up; I cannot set the authority up. Until that happens the site has no publish path at all.

Where this stops being enforceable

Honestly: whoever holds the hosting and database keys can, at the infrastructure level, do anything. Today that is me. No permission table changes that, and it would be dishonest to present one as if it did.

What makes it safe is not the table. It is that the Unit holds its own copy of everything, can read the audit trail, can revoke at will, and can take ownership of the whole project whenever it wants. The permissions stop an accident. Those four things handle the rest.

Handing it over

The end state is the Unit or the State holding the project outright, with the volunteer as an ordinary archivist account. Nothing here is designed to need me.
